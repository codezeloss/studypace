# StudyPace

StudyPace is an Android app for distance-learning students. It tracks study time per module against a weekly goal and checks whether you are on pace for the exam.

## Features

- **Individual goals:** a weekly study goal per module. You type it in, or StudyPace suggests one from the ECTS workload (25 h per ECTS) and the exam date.
- **Performance data:**
  - a focus timer that keeps running across app restarts
  - a manual form for sessions you did away from your phone
- **Evaluation:**
  - weekly progress per module and in total
  - pace status: goal reached / on track / behind
  - workload progress
  - a 6-week chart
  - a daily streak
- **History:** sessions grouped by week, filter by module, edit, and delete with undo.
- Material Design 3 UI with light and dark theme, local SQLite storage; works offline, no account needed.

## Project structure

```
src/app/        Screens and navigation (Expo Router, file-based routes)
src/domain/     Pure TypeScript logic: weeks, progress, pace, streak, timer, validation, formatting
src/data/       SQLite schema, migrations and repositories (all SQL lives here)
src/state/      Data provider and hooks (useQuery, useMutation, useNow)
src/ui/         Theme, date-picker settings, snackbar and reusable components
src/features/   Forms shared by several screens
test/           Test helpers (in-memory SQLite adapter, factories)
scripts/        Icon generator
docs/           Wireframes and screenshots
```

## How the code works

The app is built in layers; each layer only talks to the one below it.

1. **Screens** (`src/app/`) stay thin. They read data with `useQuery`, write with `useMutation`, and call domain functions for every calculation.
2. **State** (`src/state/`): the root layout (`src/app/_layout.tsx`) opens the SQLite database and runs `migrate`; `DataProvider` then creates the repositories on top of it. After every write it increases a version counter; `useQuery` re-runs its query when that counter changes or when the screen gets focus. There is no global store: the database is the single source of truth.
3. **Domain** (`src/domain/`) contains pure functions without React or device access, for example `suggestWeeklyTarget` and `paceStatus` in `pace.ts`, `weekProgress` in `progress.ts`, and `elapsedMs` in `timer.ts`. Progress values are never stored; they are recalculated from the raw sessions.
4. **Data** (`src/data/`): repositories hold all SQL and depend only on the small `Db` interface in `db.ts`. In the app, expo-sqlite implements it; in the tests, `test/sqliteAdapter.ts` wraps an in-memory better-sqlite3 database, so the real SQL is tested without a device.

Example: saving a session in the form → `validateSession` checks the input → `useMutation` calls `sessions.create` → the version counter increases → the dashboard re-reads its sessions and recalculates weekly progress, pace and streak.

The focus timer stores only timestamps (start, pause start, total paused time) in the `active_timer` table, so it survives Android pausing or killing the app.

Every exported function, type and component has a TSDoc comment that explains what it does and why.

## Getting started

Requirements: Node.js 20 or newer, and either an Android emulator (Android Studio) or a phone with **Expo Go**.

```bash
npm install
npm run android        # starts the dev server and opens the app in Expo Go on the emulator
```

On a phone: run `npm start` and scan the QR code with Expo Go.

## Tests and checks

```bash
npm test               # unit tests: domain logic + repositories against an in-memory SQLite database
npm run typecheck
npm run lint
```

## Building an APK

With EAS Build (configuration in `eas.json`):

```bash
npx eas-cli@latest build -p android --profile preview      # installable APK
npx eas-cli@latest build -p android --profile production   # app bundle for Google Play
```

Or locally (needs Android Studio / the Android SDK):

```bash
npx expo prebuild --platform android
cd android && ./gradlew assembleRelease   # APK in android/app/build/outputs/apk/release
```

`android/` and `ios/` are generated by `expo prebuild` from `app.json` and are not stored in the repository.

## Manual test checklist

1. First launch shows onboarding; "Add my first module" opens the module form.
2. Module form: invalid input shows inline errors; "Suggest" is enabled only with an exam date.
3. Focus timer: start, pause, resume, leave the screen, force-stop the app, reopen. The time is still correct.
4. Finish → rate focus → save: the session appears in History and on the dashboard.
5. Log a past session; a start time in the future is rejected.
6. Long-press a session in History → "Undo" restores it.
7. Archive a module: it leaves the weekly goal but keeps its sessions.
8. Delete a module: the dialog names the number of sessions that will be deleted.
9. Switch the system to dark mode: all screens stay readable.
